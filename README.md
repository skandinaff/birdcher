# Birdcher

Birdcher — проект автономной камеры для наблюдения за птицами на Khadas VIM3
(Amlogic A311D) с IMX415 и Armbian. Сейчас работают захват с камеры, просмотр
MJPEG в браузере и демонстрационный стрим с рамкой вокруг теннисного мяча.
Распознавание птиц и запись событий пока не реализованы. Текущее состояние и
ограничения подробно описаны в [docs/STATUS.md](docs/STATUS.md).

## Быстрый запуск на подготовленной VIM3

Команды ниже выполняются **на плате**. Они рассчитаны на установленный
камерный стек и инструменты в `/home/skf/birdcher-tools/`; исходники этих
инструментов находятся в `platform/camera/tools/` и `platform/npu/tools/`.
Плата и компьютер с браузером должны быть в одной сети.

Обычное изображение с камеры:

```sh
sudo /home/skf/birdcher-tools/preview-ctl.sh start 3600 30
sudo /home/skf/birdcher-tools/preview-ctl.sh status
```

Откройте в браузере `http://<IP-платы>:8090/` (IP выводит `status`). Первый
аргумент `start` — длительность в секундах, второй — частота кадров. Остановить
стрим можно командой:

```sh
sudo /home/skf/birdcher-tools/preview-ctl.sh stop
```

Демонстрация поиска **теннисного мяча** с рамкой поверх видео:

```sh
sudo /home/skf/birdcher-tools/npu/ball-preview-ctl.sh start 30
sudo /home/skf/birdcher-tools/npu/ball-preview-ctl.sh status
```

Адрес тот же: `http://<IP-платы>:8090/`. `ball-preview-ctl.sh` сам переключает
владельца камеры с обычного просмотра на демонстрацию. Для завершения:

```sh
sudo /home/skf/birdcher-tools/npu/ball-preview-ctl.sh stop
```

После `stop` снова запускается обычный просмотр. Одновременно открыть стрим
может один зритель; при переподключении конвейер перезапускается, а загрузка
модели может задержать первый кадр. Этот режим показывает проверку идеи, а не
готовый детектор птиц: CPU предлагает область мяча, NPU проверяет класс
`tennis ball`. Подпись `BALL?` и процент — диагностический вывод модели, не
оценка вероятности события. Подробности и измерения — в
[описании демо](docs/tasks/2026-09-16-ball-box-demo.md).

Если команды отсутствуют на плате, исходники и инструкции по сборке находятся
в [platform/README.md](platform/README.md) и
[platform/npu/README.md](platform/npu/README.md). Для режима с рамкой нужны
`ds1stream`, `ffmpeg`, `tflite-ball-stream`, библиотеки TensorFlow Lite и Mesa
Teflon, а также обе модели в `/home/skf/birdcher-tools/npu/`:
`ssdlite_mobiledet_coco_qat_postprocess.tflite` и
`mobilenet_v1_1.0_224_quant.tflite`. Модели и собранные программы в Git не
хранятся. При проблемах со стримом проверьте
`sudo systemctl status mjpeg-preview mjpeg-ball-preview` и журналы
`/tmp/birdcher-ball-{capture,inference,encoder}.log` на плате.

## Где мы сейчас и что дальше

Камера отдаёт DS1 1920×1080 NV12 через `/dev/video1`; обычный просмотр
кодируется в MJPEG. Стрим с мячом выдаёт 640×360 при примерно 30 кадрах/с,
а анализ нового кадра выполняется примерно три раза в секунду. Две
кандидатные правки Mesa дали совпадающий с CPU главный результат детектора
на трёх **сохранённых** изображениях, но качество поиска птиц ими ещё не
проверено. См. [результаты проверки Mesa](docs/tasks/2026-09-26-teflon-two-fixes.md).

Первая коллекция из iNaturalist загружена локально в `dataset/`: около 50
изображений каждого из 12 целевых видов, 50 `other_birds` и 50 кандидатов
`no_bird`. Спектрограммы, ошибочно попавшие в изображения наблюдений, удалены;
их список сохранён в `dataset/rejections.csv`. Все 50 `no_bird` просмотрены:
на сохранённом разрешении птиц не видно. Остальные метки пока требуют
проверки. [Загрузчик и локальный интерфейс проверки](tools/dataset/README.md)
позволяют продолжать отбор, отмечать сложность сцен и рисовать прямоугольники
для проверки локализации. Нужны также кадры, близкие
к будущему месту установки: маленькая птица, разные расстояния, свет, фон,
перекрытия и сложные отрицательные примеры. Отдельная часть набора должна
остаться для итоговой проверки. На одинаковых сохранённых входных данных
можно сравнить CPU и NPU, затем измерить пропуски и ложные срабатывания
относительно проверенной разметки. Совпадение NPU с CPU само по себе не
доказывает, что модель правильно узнаёт птиц.

Съёмку нового материала с IMX415 следует сначала согласовать: что находится
перед объективом, на каком расстоянии, движется ли объект и какой результат
считается успешным. Сохранённые `.rgb` и `.nv12` можно проверять повторно без
такой подготовки. Дальнейший план — в [docs/ROADMAP.md](docs/ROADMAP.md).

## Структура репозитория

- `platform/camera/` — захват и просмотр с IMX415/ISP.
- `platform/npu/` — проверка CPU/NPU, демо с мячом и кандидатные правки Mesa.
- `docs/` — состояние, архитектура, дорожная карта и результаты экспериментов.
- `external/` — закреплённые внешние исходники драйверов; Khadas используется
  как эталон поведения G12B, без правок внутри субмодуля.
