# M2: A311D NPU proof

Started 2026-09-16 on Khadas VIM3, Armbian 26.8.3, kernel
`6.18.44-current-meson64`.

## Installed stack

| Component | Board result |
| --- | --- |
| Kernel | `etnaviv` bound to `ff100000.npu`, GC8000 revision 7120; render node `/dev/dri/renderD128` |
| Mesa | `mesa-libgallium` 26.0.8; `mesa-teflon-delegate` 26.0.8-1ubuntu0.3 |
| TensorFlow Lite | `libtensorflow-lite-dev` / runtime 2.14.1+dfsg-3build1 |
| Model | Official MobileNet V1 224 UINT8, SHA-256 `ecc3a67c47c5a609ec35f6a58a7d97532834e43df4cb7d3f1204a8164b7d20dd` |

Reproduction commands and source code are in
[`platform/npu/`](../../platform/npu/README.md). Mesa's
[official delegate documentation](https://docs.mesa3d.org/teflon.html)
lists this NPU and model as tested. The
[Ubuntu package](https://packages.ubuntu.com/resolute-updates/mesa-teflon-delegate)
avoids a custom Mesa build.

## First CPU/NPU comparison

On a deterministic synthetic UINT8 input, 50 warm-invocation runs with one
CPU thread:

| Path | Mean inference | Top output index/value |
| --- | ---: | ---: |
| TFLite CPU | 93.8561 ms | 754 / 145 |
| Mesa Teflon → etnaviv → NPU | 6.70056 ms | 754 / 138 |

The measured inference speedup is 14.0×. Eight of 1001 output bytes differed;
maximum absolute difference 7 quantization levels and mean absolute
difference 0.01998. The top output index matched. `TEFLON_DEBUG=verbose`
reported the etnaviv driver loaded, 27 operations compiled into an NPU graph,
and hardware NN-job timings during invocation. The remaining average-pooling
and softmax operations ran outside that graph. This confirms actual NPU work,
not merely a delegate library loading successfully.

## Stability

A 550,000-invocation NPU-only run started at 2026-09-16 21:20 EEST as the
transient `birdcher-npu-soak.service` systemd unit under user `skf`. It was
intentionally stopped after roughly 15 minutes to free the board for the live
camera demo. It did **not** complete the one-hour target. For a future
uninterrupted run, check the result and kernel log before marking M2 complete:

```sh
systemctl show birdcher-npu-soak -p ActiveState -p Result -p ExecMainStatus
cat ~/birdcher-tools/npu/stress.log
journalctl -k --since '2026-09-16 21:20:14' | grep -Ei 'etnaviv|npu|fault|reset|oops|bug|warning'
```

## Real-image ball demo

The user placed a white tennis ball in the camera's view. On the second frame,
the ball was unobstructed and about 400 px across. A 600×600 crop from the
1920×1080 DS1 frame was resized to the model's 224×224 RGB input. Twenty
steady-state inferences per backend gave:

| Path | Mean inference | Top class | Quantized output value |
| --- | ---: | --- | ---: |
| TFLite CPU | 94.1543 ms | tennis ball (index 853) | 56 |
| Mesa Teflon / NPU | 6.92692 ms | tennis ball (index 853) | 51 |

The NPU path was 13.59× faster on this crop and picked the same top class.
Eighteen of 1001 output bytes differed; maximum difference was five. The
values above are raw quantized model outputs, not probabilities. A tighter
450×450 crop also put tennis ball first on both backends (CPU 68, NPU 69;
13.89× speedup). The earlier cluttered frame did not classify correctly, so
crop and image quality are material to the demo. The JPEG and raw frame are
kept on the board under `~/birdcher-tools/npu/`, outside Git.

The COCO SSDLite MobileDet object detector remains unresolved. On the new
full frame, its CPU path labeled the ball region as `apple` (score 0.488),
while its Teflon path returned zero detections. On a control soccer-ball
photo, CPU found `sports ball` at score 0.465 and Teflon again returned zero.
Thus the classification demo proves this MobileNet model works on the NPU;
it does not prove NPU object detection or localization. Investigate the
detector mismatch and measure thermal behaviour before camera integration.
M2 is **in progress**.
